# Observer 2.0

Observer следит за **видимым** изображением ArcheAge на Windows 11. Когда в выбранной области появляется движение транспорта, программа показывает его на снимке и отправляет сообщение во все подключённые Discord, Telegram и ВК. При потере обзора сообщает об этом отдельно. Долго стоящий объект не вызывает повторные сообщения.

## Запуск

Скачайте архив `Observer-2.0-win-x64.zip` из [Releases](https://github.com/sheezeeq/Observer/releases), распакуйте **все файлы в одну папку** и запустите `Observer.exe`. Установка .NET не требуется. Файл `yolox_nano.onnx` должен лежать рядом с `Observer.exe`.

Для сборки из исходников нужен .NET 10 SDK:

```powershell
dotnet publish Observer.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o dist
```

## Настройка

1. Откройте ArcheAge и выберите её окно. Режим захвата **Автоматически** берёт область игры в оконном режиме и весь экран, если игра занимает почти весь дисплей. Вручную можно выбрать **Окно игры** или **Весь дисплей**.
2. Введите название точки наблюдения и данные нужных каналов. Можно подключить один, два или все три канала. При настройке Telegram боту нужны право писать в чат и `chat_id` этого чата. Для ВК нужны ключ сообщества и числовой `peer_id` диалога или беседы.
3. Нажмите **Обновить снимок** и выделите на нём область наблюдения. По возможности исключите чат, интерфейс и постоянные анимации.
4. Нажмите **Тестовое сообщение**. Программа отправит отдельное сообщение в каждый подключённый канал и покажет результат каждого. Если открыт снимок, он будет приложен. Затем нажмите **Сохранить настройки**.
5. Нажмите **Начать наблюдение**. Observer свернётся и вернёт фокус игре. Для остановки откройте его с панели задач.

Снимок события содержит красную обводку объекта. Название показывается, когда модель распознала категорию. Поддерживаются широкие категории «Судно» и «Наземный транспорт»; названия «Трактор», «Галеон» и «Фрегат» выводятся только при уверенном совпадении с шаблонами из предоставленных игровых кадров. По умолчанию включены сообщения и о неопознанном движении. Эту опцию можно выключить после настройки области и проверки в игре.

Неотправленные события остаются в локальной очереди и повторяются после ошибки канала. Каждому каналу соответствует свой элемент очереди. Снимки и настройки находятся в `%LOCALAPPDATA%\Observer`; последние 100 снимков сохраняются в `events`. Ключи и вебхук защищены средствами Windows для текущей учётной записи. Не публикуйте `settings.json`.

## Важные ограничения

- Модель YOLOX-Nano проверена на предоставленных снимках, но пороги и названия видов транспорта ещё требуют проверки на живой игре. Похожие суда, другие машины, интерфейс и погода могут вызвать ложные срабатывания или пропуски.
- Захват оконного и занимающего весь дисплей изображения реализован через видимые пиксели экрана. Безрамочный и полноэкранный режимы предусмотрены, но **эксклюзивный полноэкранный режим на вашем клиенте пока не проверен**. Свёрнутую игру Observer не видит. Если снимок чёрный, переключите режим захвата и проверьте его снова.
- Реальная доставка в Discord, Telegram и ВК требует ваших собственных реквизитов и пока не проверена в живых чатах. Кнопка **Тестовое сообщение** предназначена именно для этой проверки.
- На слабом ноутбуке нагрузка зависит от разрешения экрана и числа движущихся объектов. Для снижения нагрузки модель обрабатывает уменьшенный кадр двумя потоками ЦП и запускается при появлении движения.

Приложение анализирует только изображение экрана. Оно не читает память игры и не отправляет игровые команды. Исходные игровые снимки в публичный репозиторий не добавлены. Сведения о сторонней модели и лицензиях находятся в [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).
